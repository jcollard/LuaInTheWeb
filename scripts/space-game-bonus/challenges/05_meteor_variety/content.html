New Concepts

  • Per-object data: right now every meteor shares meteor_w, meteor_h and meteor_speed. To make meteors different, each meteor table needs its own meteor.w, meteor.h and meteor.speed.
  • Refactoring: changing how your code stores things without changing what the game does. When you move data, you must update every place that used the old names.
  • Picking from a list: kinds[math.random(#kinds)] picks one random entry from a list. With only one number in the parentheses, math.random gives a whole number from 1 up to that number. Here that number is the length of the list.
  • math.random() with no arguments gives a decimal between 0 and 1 (like 0.73). Multiply and subtract to get any range you want.
  • Transforms: canvas.save(), canvas.translate(x, y), canvas.rotate(radians) and canvas.restore() let you move and turn everything you draw.

CHALLENGE Task 2: Each meteor picks a kind
Change spawn_meteor() so it picks a random kind from meteor_kinds, then copies that kind's w, h, speed and image into the new meteor table. Use the kind's width and height (not meteor_w and meteor_h) for the starting x and y too.
#meteor_kinds is 3. math.random(3) gives 1, 2 or 3. Use that number to pick a position in the list.
Start with local kind = meteor_kinds[math.random(#meteor_kinds)]. Then inside the meteor table write w = kind.w, and so on for each field.
local function spawn_meteor()
    local kind = meteor_kinds[math.random(#meteor_kinds)]
    local meteor = {
        x = math.random(0, SCREEN_W - kind.w),
        y = -kind.h,
        w = kind.w,
        h = kind.h,
        speed = kind.speed,
        image = kind.image
    }
    table.insert(meteors, meteor)
end

CHALLENGE Task 4: Give each meteor a spin
Add two more fields to each new meteor: angle (starts at 0) and spin, a random number between -2 and 2. Then, in the meteor movement loop, add spin * dt to the meteor's angle every frame.
Angles here are in radians, which measure angles the way degrees do. A full turn (360 degrees) is about 6.28 radians, so a spin of 2 is roughly one turn every three seconds. A negative spin turns the other way.
math.random() gives 0 to 1. math.random() * 4 gives 0 to 4. What do you subtract to get -2 to 2?
In spawn_meteor() add angle = 0, and spin = math.random() * 4 - 2. In update(), the angle grows just like y does: meteors[i].angle = meteors[i].angle + meteors[i].spin * dt.
-- In spawn_meteor(), add to the meteor table
image = kind.image,
angle = 0,
spin = math.random() * 4 - 2

-- In update(), in the meteor movement loop
meteors[i].angle = meteors[i].angle + meteors[i].spin * dt

Where: DRAW section, replace the whole meteor drawing loop
-- Meteors (spinning around their centers)
for i, meteor in ipairs(meteors) do
    canvas.save()
    canvas.translate(meteor.x + meteor.w / 2, meteor.y + meteor.h / 2)
    canvas.rotate(meteor.angle)
    canvas.draw_image(meteor.image, -meteor.w / 2, -meteor.h / 2, meteor.w, meteor.h)
    canvas.restore()
end
canvas.rotate() always turns around the point (0, 0). Normally that's the top-left corner of the screen, so rotating there would swing the meteor in a big circle across the screen! Instead, translate first moves (0, 0) to the center of the meteor. Then rotate turns around that center. The last line draws the image half its width to the left and half its height up (-meteor.w / 2, -meteor.h / 2). That way the image sits centered on the new (0, 0). canvas.save() remembers the normal canvas and canvas.restore() puts it back, so the next meteor, the ship and the HUD aren't moved or turned. Every save needs a matching restore. If one is missing, everything drawn after it stays moved and turned.

Check Your Work

Run game.lua. You should see:

  • Three kinds of meteors: small, medium and big
  • Small meteors fall fast, big ones fall slowly
  • Every meteor spins, some clockwise and some counter-clockwise, at different speeds
  • Meteors spin in place around their centers (they don't swing around the screen)
  • Lasers hit, and the ship crashes into, each meteor at its own size

Collisions still use rectangles that don't spin, so the very corner of a meteor's box can count as a hit. That's fine for a fast game like this one.
