How to design a feature

Every challenge you've done followed the same four questions. Use them for your own idea:

  1. What data does it need? New variables? A new list of tables? New fields on meteors or lasers?
  2. What changes it? Which keys, timers, or collisions change that data? That code goes in user_input() or update().
  3. How does the player see it? What do you draw, and in what order? That code goes in draw().
  4. How does it start over? What needs to go back to normal in reset_game()?

Most features are built from patterns you already know: timers, lists of tables, reverse loops for removing, and collision checks.

CHALLENGE Task 1: Pick an idea
Pick one idea from the list below, or invent your own. Start small — you can always add more later.
Ideas:
  • Homing missile — press X to fire a slow missile that turns toward the nearest meteor.
  • Combo multiplier — hitting meteors quickly in a row doubles, then triples, your points. Missing for 2 seconds resets it.
  • Splitting meteors — big meteors break into two small ones that fly apart.
  • Bomb — press B to destroy everything on screen. You only get 3 per game.
  • Coins and a shop — destroyed meteors drop coins. Between games, spend them on upgrades.
  • Two players — a second ship controlled with WASD and F to fire.
  • Black hole — a black hole drifts across the screen and pulls the ship and meteors toward it.
Not sure which one? Pick the one that sounds most fun to play. The combo multiplier and the bomb are the smallest; two players and the shop are the biggest.
Write your idea as one sentence that starts with "When the player..." For example: "When the player presses B, every meteor on screen explodes and the bomb count goes down by one."
CHALLENGE Task 2: Plan it on paper
Before writing code, answer the four questions from the top of this page for your idea. Write the answers as comments at the top of game.lua.
Here's a plan for the bomb idea: 
-- MY FEATURE: Bombs
-- Data:    bombs = 3
-- Changes: pressing B (if bombs > 0) clears meteors, adds to score, bombs - 1
-- Draw:    "Bombs: 3" in the HUD, a white flash when one goes off
-- Reset:   bombs = 3 in reset_game()
If your plan has more than about five "Changes" lines, split it into a smaller first version. Get that working, then add the rest.
CHALLENGE Task 3: Build it one piece at a time
Build your feature in small steps, running the game after each one: data first, then drawing (so you can see it), then the logic that changes it, and finally the reset.
Drawing early is a debugging trick: if you can see your new data on screen (even just as text in the HUD), it's much easier to tell when the logic is wrong.
Stuck on an error? Read the line number in the error message, then look at that line and the line above it. Missing ends and misspelled variable names are the most common causes.
Look back at a bonus challenge that used a similar pattern. Splitting meteors works a lot like Explosion Particles. A homing missile uses the same math.cos/math.sin idea. Combos are timers, like Fire Cooldown.
CHALLENGE Task 4: Playtest and tune
Play your game five times. After each game, change one number (a speed, a timer, a cost) to make it more fun. Then ask someone else to play it without telling them how it works — can they figure it out?
If a number is hard to tune, give it a name in ALL_CAPS at the top of the file (like BOMB_COUNT = 3) so it's easy to find and change.
If your playtester gets confused, add a line to the HUD or the title screen explaining the new key or rule.

Check Your Work

Your feature is done when:

  • It adds at least one new thing (a new object, rule, or ability)
  • The player can see it working (a drawing, a HUD value, an effect)
  • It resets correctly when you press ENTER after a game over
  • The rest of the game still works: moving, shooting, scoring, and game over
  • Someone else can play it and understand it

There's no reference solution for this one — it's your game now.

Going Further

  • Combine several bonus challenges into one game. Which features work well together?
  • Give your game a new name and title screen, and change the ship's color (there are more ships in Kenney's free Space Shooter pack at kenney.nl).
  • Make a second game from scratch using the same patterns: a dodging game, a falling-object catcher, or a top-down racer.
