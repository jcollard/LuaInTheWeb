New Concepts

  • Screen shake — for a split second, draw the whole game world a few pixels off in a random direction. Each frame picks a new direction, so it looks like the screen is shaking.
  • canvas.translate(dx, dy) — moves everything drawn after it by dx pixels right and dy pixels down. You don't have to change any of your x and y values.
  • canvas.save() and canvas.restore() — save remembers the canvas as it is now; restore undoes every translate since then. Every save needs a matching restore.
  • math.random() with no arguments gives a decimal between 0 and 1. So math.random() * 2 - 1 gives a decimal between -1 and 1.
CHALLENGE Task 1: Shake variables and a start_shake function
In GAME STATE, add three variables that all start at 0: shake_time (seconds of shaking left), shake_length (how long the current shake lasts in total) and shake_strength (how many pixels the screen can move). Then write a function start_shake(strength, length) that sets shake_strength to strength, and sets both shake_length and shake_time to length.
You won't need shake_length until Task 5, where it lets the shake fade out smoothly.
Put the function in its own section above spawn_meteor(), so the collision code in update() can call it.
The function body is just three lines: shake_strength = strength, shake_length = length, shake_time = length.
-- Screen shake
local shake_time = 0      -- seconds of shaking left
local shake_length = 0    -- how long the current shake lasts in total
local shake_strength = 0  -- how many pixels the screen can move

-- ============================================================
-- START SHAKE
-- ============================================================

local function start_shake(strength, length)
    shake_strength = strength
    shake_length = length
    shake_time = length
end

Call start_shake in two places: a small, quick shake (4 pixels for 0.15 seconds) when a laser destroys a meteor, and a big, longer shake (12 pixels for 0.5 seconds) when the ship crashes.
Look in update() for the line that adds to the score, and the line that sets game_over = true.
Add start_shake(4, 0.15) after score = score + 1 (before the break), and start_shake(12, 0.5) after game_over = true (before the return).
-- Laser vs meteor collision
score = score + 1
start_shake(4, 0.15)

-- Ship vs meteor collision
game_over = true

CHALLENGE Task 3: Count the shake down
In update(), subtract dt from shake_time every frame (never going below 0). It must keep counting down even after the game is over. Also make reset_game() set shake_time back to 0.
Watch out: the very first line of update() is if game_over then return end. Once the ship crashes, nothing below that line runs any more. If your countdown is below it, the big crash shake would start… and never stop!
The countdown needs to go above the game_over check. But it uses dt, so the local dt = canvas.get_delta() line has to move up too.
Move local dt = canvas.get_delta() to the top of update(). Then add shake_time = math.max(0, shake_time - dt). Then the if game_over then return end line.
local function update()
    local dt = canvas.get_delta()

    -- Count down the shake (before the game over check,
    -- so the game over shake can still stop)
    shake_time = math.max(0, shake_time - dt)

    if game_over then return end

    -- ... the rest of update() is the same ...

shake_time = 0
CHALLENGE Task 4: Shake the world, not the HUD
In draw(), right after the dark background, call canvas.save(). If shake_time is above 0, pick a random dx and dy between -shake_strength and shake_strength and call canvas.translate(dx, dy). Then, right after drawing the ship (before the HUD), call canvas.restore().
Why not shake everything? The stars, lasers, meteors and ship are in the world, so they should jolt. The score and the game over text are like a sticker on the glass of your screen. If they shake, they're hard to read, and it looks like the whole TV is broken. The background stays still too: it already fills the whole screen, and moving it would show black gaps at the edges.
math.random() * 2 - 1 is between -1 and 1. Multiply that by shake_strength.
Your draw order should be: clear, background, save, (maybe translate), stars, lasers, meteors, ship, restore, HUD, game over overlay.
Inside if shake_time > 0 then: local dx = (math.random() * 2 - 1) * shake_strength, the same for dy, then canvas.translate(dx, dy). Keep save and restore outside the if so they always come in a pair.
-- Shake the game world (but not the background or HUD)
canvas.save()
if shake_time > 0 then
    local dx = (math.random() * 2 - 1) * shake_strength
    local dy = (math.random() * 2 - 1) * shake_strength
    canvas.translate(dx, dy)
end

-- ... stars, lasers, meteors, ship ...

-- Stop shaking: everything after this stays still
canvas.restore()
CHALLENGE Task 5: Fade the shake out
Right now the shake is full strength until it stops dead. Make it fade instead: full strength when the shake starts, getting smaller as shake_time runs out, and reaching 0 right at the end.
shake_time / shake_length is the fraction of the shake left. It's 1 when the shake starts, 0.5 halfway through, and 0 at the end.
Make a local power = shake_strength * shake_time / shake_length and use power instead of shake_strength when you pick dx and dy.
if shake_time > 0 then
    local power = shake_strength * shake_time / shake_length
    local dx = (math.random() * 2 - 1) * power
    local dy = (math.random() * 2 - 1) * power
    canvas.translate(dx, dy)
end

Check Your Work

Run game.lua. You should see:

  • A quick little jolt each time you destroy a meteor
  • A big shake when your ship crashes, that settles down after half a second

  • No black gaps at the edges of the screen while shaking
  • Pressing ENTER after a game over starts a calm new game

Going Further

  • If a small shake starts during a big one, it cuts the big one short. Change start_shake so it never replaces a stronger shake that's still going.
  • Tune the numbers. Too much shake makes players feel sick, too little and nobody notices. What feels best?
  • Add a red flash over the whole screen when the ship crashes, fading out with its own timer.
